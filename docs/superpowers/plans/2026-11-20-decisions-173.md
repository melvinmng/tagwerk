## Global Constraints

- **Bestätigung vor jedem Schreiben** bleibt: jedes schreibende Werkzeug ist eine Karte; nichts wird ohne Tipp oder gesprochenes „Ja“ ausgeführt.
- **Abgabe-Regel (Entscheidung 2):** Verlässt der Nutzer ein Issue, werden nur Zeitblöcke gelöscht, die nach dem Moment der Abgabe beginnen (`BlockPlanner.deleteFutureBlocks(of:after:)` über `PlanningModel.didHandOver`); vergangene bleiben. Die Anzahl steht vor der Bestätigung auf der Karte.
- Zuweisungen werden nur als Differenz geschrieben (`AssigneeChange`, erst hinzufügen, dann entfernen); höchstens 10 Personen (`AssigneeRules.maximum`); Logins ohne Groß-/Kleinschreibung verglichen, geschrieben in GitHubs Schreibweise.
- Kein blindes Zuweisen: jede hinzugefügte fremde Person muss in `assignableUsers(in:)` des Repositories stehen; lädt die Liste nicht, wird nichts geschrieben.
- **Private Notizen verlassen das Gerät nie:** `NoteKind.isPrivate`, `NoteFolderRole.isPrivate` und alle Unterordner privater Ordner. Die Prüfung liegt in einer reinen Funktion in `TagwerkCore` und wird an genau einer Stelle für das Suchwerkzeug angewendet.
- Kein Notiztext in Logs, Fehlermeldungen oder im gespeicherten Chatverlauf (D4).
- iOS hält 64 ausstehende Mitteilungen je App: die Summe in `NotificationBudget` bleibt 64 (`NotificationBudgetTests`).
- Texte: Deutsch im Quelltext, Englisch im Katalog. **Jeder Task trägt seine neuen Zeichenketten selbst ein** (`scripts/sync-strings.sh`, dann Englisch in `scripts/translations/en.json` und `scripts/apply-translations.py`), sonst wird `app/test-all.sh` in der Stufe „string catalogs“ rot. Werkzeugbeschreibungen für das Modell bleiben englisch, die Systemanweisung deutsch (wie bisher).
- Code-Bezeichner, Kommentare, Log- und Testmeldungen englisch. Commits im Stil `feat: …`/`fix: …`, ohne Hinweis auf KI, ohne Co-Authored-By.
- Neue Parameter haben Standardwerte; bestehende Aufrufer und Tests bleiben gültig.

**Testbefehle** (wie in `2026-11-19-issue-assignees.md`):

## Review Focus

1. **Abgabe über das Werkzeug löscht nur künftige Blöcke** und meldet deren Zahl; ein Fehler beim Entfernen (nach erfolgreichem Hinzufügen) lässt das Issue in der Liste und löscht nichts. → Task 1 (`assignTask_handOver_deletesOnlyFutureBlocks`, `assignTask_removeFails_keepsBlocks`).
2. **Karte und Ausführung stimmen überein:** Die Karte rechnet „danach zugewiesen“ aus demselben Stand wie die Ausführung; ändert sich der Stand dazwischen (Konflikt), wird nichts geschrieben. → Task 1, Task 2.
3. **„Alle bestätigen“ führt nie eine Abgabe aus**, weder im Chat noch per Sprache noch in den Notiz-Vorschlägen. → Task 2 (`confirmAll_skipsGuardedCards`).
4. **Private Notizen:** Tagebuch, Bible Study, Dream Log, eigene Notizen in einem privaten Ordner, Notizen in einem Unterordner eines privaten Ordners und Notizen im Papierkorb erscheinen nie in `search`, auch nicht als Zähler. → Task 3 (`privateFolderIDs_includesSubfolders`, `search_excludesPrivateNotes`).
5. **Gespeicherter Verlauf ohne Notiztext:** nach Zugende, bei offenem Kartenstand und nach App-Abbruch mitten im Zug. → Task 4 (`persist_redactsNoteTextWhileCardsAreOpen`).
6. **Online-Suche nur auf Anforderung:** ohne `github_online: true` kein Netzaufruf. → Task 3 (`search_withoutFlag_doesNotCallGitHub`).
7. **Zeitzone bei `closedAt`:** ein um 00:30 Ortszeit geschlossenes Issue zählt zum richtigen Tag, auch wenn das UTC-Datum abweicht. → Task 6 (`closedIssues_filtersByLocalInterval`).
8. **Notiz-Vorschlag mit unklarem Ziel** wird nie ausgeführt, auch nicht über „Alle bestätigen“. → Task 8 (`confirmAll_skipsUnresolvedIssueCards`).
9. **Abend-Erinnerung nach Mitternacht:** Schlafzeit 00:30, Abstand 15 → 00:15 gehört zum Routinetag davor (Regel 10); abgehakt am Vorabend heißt: keine Mitteilung um 00:15. → Task 10 (`eveningNotifications_afterMidnightBelongToPreviousRoutineDay`).
10. **Budget:** höchstens 12 Abend-Mitteilungen, 14 Routine-Mitteilungen insgesamt, Summe 64. → Task 10, Task 11.

/// What an `assign_task` call resolves to; shared by execution and confirmation card.
struct AssignmentPlan: Equatable {
    let change: AssigneeChange      // GitHub's spelling, each person once, add ∩ remove rejected
    let before: [String]
    let after: [String]             // AssigneeRules.applying(change, to: before)

enum AssignmentError: Error, Equatable { case notAnIssue, nothingToChange, tooMany, notAssigned([String]), conflicting([String]) }
static func assignmentPlan(current: [String], add: [String], remove: [String], me: String?) -> Result<AssignmentPlan, AssignmentError>
func assignTask(_ args: Arguments) async throws -> String

## Risiken

| Risiko | Folge | Gegenmaßnahme |
|---|---|---|
| Modell entfernt den Nutzer, obwohl nur „zusätzlich zuweisen“ gemeint war | ungewollte Abgabe | Karte nennt „nicht mehr dir“ und die Blöcke, roter Knopf, nie in Sammelbestätigung (D2) |
| Abgabe ist nicht umkehrbar (Blöcke weg, Issue aus der Liste) | Datenverlust in der Planung | Zahl der Blöcke auf der Karte; Antwort enthält Nummer und Link zum Zurückholen |
| Assistent zitiert einen Notiz-Ausschnitt in seiner Antwort | Ausschnitt bleibt im Verlauf | Anweisung untersagt wörtliche Wiedergabe; als Grenze in D4 und im Fußtext des Schalters benannt; nicht technisch erzwingbar |
| Kürzung nimmt dem Modell den Kontext für Folgefragen („zeig mir die zweite“) | Assistent muss erneut suchen | Kennung, Art, Datum bleiben; erneute Suche ist billig und lokal |
| GitHub-Suche: `closed:>=` rundet auf UTC-Tage; mehr als 50 Treffer | Zählung zu niedrig | Abfrage ab Vortag, Filter auf dem Gerät; 50 geschlossene eigene Issues in zwei Tagen sind unwahrscheinlich, die Grenze steht im Kommentar |
| Issues, die nur im Project auf „Done“ stehen | zählen nicht | in D6 benannt; Tagwerk selbst schließt beim Erledigen das Issue |
| Suchrate von GitHub (30 Anfragen je Minute) | Tagesabschluss zeigt „nicht erreichbar“ | eine Anfrage je Öffnen des Blatts; lokale Zahlen bleiben |
| App wird länger als 3 Tage nicht geöffnet und der Hintergrund-Refresh bleibt aus | Abend-Erinnerungen hören auf | Refresh füllt nach (Task 11); Fußtext sagt es; D9 lässt 2 statt 3 Tage nur mit Begründung zu |
| 4 Plätze weniger für Aufgaben/Deadlines | spätere Mitteilungen kommen erst nach dem Nachfüllen | rollierender Plan mit `nextRefill` besteht; Test für die Grenze 46 |
| Altbestand wiederholender Abend-Mitteilungen nach dem Update | doppelte Mitteilungen | erster Lauf entfernt alle `tagwerk.routine.*` (Test `reschedule_removesOldRepeatingEveningRequests`) |
| Notiz-Vorschlag rät ein falsches Repository aus dem Notiztext | Issue im falschen Repository | nur eindeutige Treffer; Ziel steht vor der Bestätigung auf der Karte und ist änderbar |
| Strang A und B ändern dieselben Dateien | Merge-Konflikte bei paralleler Arbeit | Reihenfolge 1 → 5 einhalten; nur C und E parallel |
