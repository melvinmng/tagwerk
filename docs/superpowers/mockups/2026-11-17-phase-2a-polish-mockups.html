Empfehlung 1A

Einzige Variante, die Bestätigung, Kontext und Aktion an einer festen, einhändig erreichbaren Stelle bündelt. Die Frist wird sichtbar, statt den Balken kommentarlos verschwinden zu lassen.
  • Dynamic Type: Titel maximal 2 Zeilen; ab Bedienungshilfen-Größen per ViewThatFits Taste unter den Text, Form wechselt von Kapsel zu abgerundetem Rechteck (Radius 22).
  • VoiceOver: Beim Erscheinen AccessibilityNotification.Announcement("Erledigt: … Rückgängig verfügbar"); Taste mit Label „Rückgängig“, Hinweis „Markiert die Aufgabe wieder als offen“. Ring ist dekorativ (.accessibilityHidden).
  • Frist: 4 s sind für Screenreader-Nutzung zu kurz (WCAG 2.2.1, anpassbare Zeitlimits). Vorschlag: 5 s regulär, bei aktivem VoiceOver/Schaltersteuerung kein Auto-Ausblenden bis zur nächsten Aktion. Bei „Bewegung reduzieren“ Ring statisch, Ein-/Ausblenden nur per Deckkraft.
  • Kontrast: Weißer Text auf Glas; Haken schwarz auf Systemgrün. Farbe trägt nie allein die Bedeutung (Haken-Symbol + Wort „Erledigt“).
  • SwiftUI: bestehendes .safeAreaInset(edge: .bottom) behalten; Inhalt HStack { Image(systemName: "checkmark.circle.fill"); VStack{…}; Button{…} } mit .glassEffect(.regular, in: .capsule), Taste .buttonStyle(.glass) bzw. getönt. Ring: Circle().trim(from: 0, to: rest).stroke(), linear über die Frist animiert. .transition(.move(edge: .bottom).combined(with: .opacity)), .sensoryFeedback(.success, trigger: completed.id).

2 · Konflikt-Banner im Editor

Ist-Zustand: orange Fläche mit orangem Text und zwei Textlinks. Schwächen: sagt nicht, was sich geändert hat; die Folgen beider Aktionen bleiben unklar (was geht verloren?); orange Schrift auf hellem Grund verfehlt im Hellmodus 4,5:1. Der Konflikt entsteht beim Sichern (TaskWriteError.conflict(current:)); der frische Stand liegt vor, die Differenz original → conflict und original → draft ist also berechenbar. Beispiel: eigene Änderungen an Priorität (P2 → P1) und Geschätzt (1 h → 1,5 h).

Empfehlung 2A

Der Kern des Problems ist fehlende Information, nicht die Farbe. Nur 2A zeigt die geänderten Felder mit Alt- und Neu-Wert, trennt harmlose Änderungen (Fällig, Labels: bleiben erhalten) von echter Überschneidung (Priorität) und benennt die Folge jeder Taste. Die Funktion bleibt unverändert.
  • Tastenhierarchie: „Trotzdem sichern“ ist hervorgehoben, weil es die begonnene Absicht (Sichern) fortsetzt; „Neu laden“ ist neutral. Keine rote Rolle: beides ist legitim, die Fußzeile nennt den Verlust. Ohne Überschneidung entfällt die Warnzeile, die Fußzeile lautet dann „… überschreibt nichts auf GitHub“.
  • Nach „Neu laden“: Karte verschwindet mit Animation, Felder zeigen den Quellstand; kurze VoiceOver-Ansage „Stand von GitHub geladen“.
  • Kontrast: Fließtext in .primary/.secondary; Orange nur für Symbol, Rahmen und die eine Warnzeile (dort mit Symbol ⚠︎, nicht nur Farbe). Behebt das Hellmodus-Problem der bisherigen Vollorange-Schrift.
  • Dynamic Type: Diff-Zeilen als LabeledContent, brechen bei großen Schriften untereinander um; Tasten stapeln sich per ViewThatFits vertikal.
  • VoiceOver: Karte als Container „Konflikt“; jede Zeile ein Element: „Priorität, auf GitHub von P2 zu P3 geändert, du hast P1 gewählt“. Beim Erscheinen Fokus auf die Überschrift (.accessibilityFocused), weil die Karte nach dem Tippen auf „Sichern“ oben außerhalb des Fokus entsteht.
  • SwiftUI: eigene Section oben im Form (wie bisher), darin VStack mit Label, ForEach(changes) { LabeledContent($0.name) { Text("\(alt) → \(neu)") } }, zwei Button mit .buttonStyle(.bordered) / .borderedProminent, .buttonBorderShape(.capsule), .controlSize(.large). Rahmen über .listRowBackground mit RoundedRectangle().strokeBorder(.orange.opacity(0.45)). Neu nötig: Funktion, die aus original, draft und conflict die Liste [FieldChange(field, old, new, collidesWithDraft)] bildet; ScrollViewReader.scrollTo zur Karte beim Auftreten.

3 · Geschätzter Aufwand in Stunden

Ist-Zustand: Stepper in Minuten (Schritt 15, Anzeige „60 min“), keine Direkteingabe. Anforderung: Stunden ab 0,25 in 0,25er-Schritten, Tippen und +/−. Gemeinsame Regeln für alle Varianten: Dezimalkomma aus der Locale; Bereich 0,25–24 h; Eingabe wird beim Verlassen auf das nächste Viertel gerundet und begrenzt; leer = „kein Aufwand“; gespeichert wird weiter estimateMinutes (Stunden × 60), das Datenmodell bleibt unverändert.

Empfehlung 3A

Erfüllt „tippen und +/−“ in einem sichtbar zusammengehörenden Element und ohne Zusatztipp. Schnellwerte und „Kein“ machen die häufigsten Eingaben und das Leeren zu Ein-Tipp-Aktionen. 3B ist die Rückfalloption, falls der Aufwand minimal bleiben soll.
  • Format: „0,25 h“, „1 h“, „1,5 h“ (0–2 Nachkommastellen, Locale-Komma). Auch die Listen-/Planungsanzeige sollte von „60 min“ auf dieses Format wechseln, sonst entstehen zwei Einheiten.
  • Dynamic Type: Bei Bedienungshilfen-Größen Kapsel per ViewThatFits unter die Beschriftung; Schnellwerte in horizontalem ScrollView, nichts wird abgeschnitten.
  • VoiceOver: Gesamtes Element als anpassbarer Wert: Label „Geschätzter Aufwand“, Wert „0,75 Stunden“ bzw. „kein Aufwand“, Wischen hoch/runter = ±0,25 (.accessibilityAdjustableAction). Schnellwerte mit Label „1 Stunde“ und Trait „ausgewählt“.
  • Erreichbarkeit/Kontrast: −/+ je 44 × 36 pt mit erweitertem contentShape; deaktiviertes − (leerer Zustand) bleibt sichtbar, ist aber auch für VoiceOver als „nicht verfügbar“ markiert.
  • SwiftUI: LabeledContent("Geschätzt") { HStack { Button(−); TextField("–", value: $hours, format: .number.precision(.fractionLength(0...2))).keyboardType(.decimalPad).multilineTextAlignment(.center).focused($focus); Text("h"); Button(+) } .background(.quaternary, in: .capsule) }; Tasten mit .buttonRepeatBehavior(.enabled) und .buttonStyle(.borderless) (sonst löst im Form die ganze Zeile aus). Schnellwerte: ScrollView(.horizontal) { ForEach([0.25, 0.5, 1, 2, 4]) { Button … } } mit .buttonStyle(.bordered), .buttonBorderShape(.capsule). „Fertig“ über .toolbar { ToolbarItemGroup(placement: .keyboard) }. Runden/Begrenzen in einem Binding<Double?> auf estimateMinutes sowie in .onChange(of: focus).

Empfehlung 4A (mit den gedimmten Kreisen aus 4C)

Die Leiste ist der native Ort für einen Zustand, der die ganze Liste betrifft; das Symbol ist die leiseste Form, die trotzdem dauerhaft sichtbar bleibt. Die gedimmten Kreise beantworten zusätzlich an der Zeile, warum sich ein Issue nicht abhaken lässt. Die wiederholten Wolken-Symbole aus 4C entfallen.
  • Sichtbarkeit: Symbol nur, solange sourceStates[.github]?.isOffline == true; beim ersten Wechsel in den Offline-Zustand einmalig .symbolEffect(.bounce), danach statisch. Die bisherige .offline-Zeile in SourceProblemRow entfällt; .failed, .noAccess, .signedOut bleiben Zeilen, weil sie eine Handlung verlangen.
  • Schreibschutz an der Zeile: Tippen auf einen gedimmten Kreis öffnet dasselbe Popover (heute passiert bei !isWritable nichts, was wie ein Defekt wirkt). Wischaktionen bleiben wie bisher ausgeblendet.
  • VoiceOver: Symbol-Label „GitHub offline“, Wert „Stand 17. November, 14:05“, Hinweis „Zeigt Details“. Gesperrte Zeilen erhalten den Zusatz „nur lesbar, GitHub offline“, damit der Zustand nicht allein über Deckkraft vermittelt wird.
  • Dynamic Type / Kontrast: SF-Symbol skaliert mit; Sekundärgrau auf Leistenhintergrund liegt als Grafik über 3:1. Popover-Text in .primary, umbricht frei. Kein Orange oder Rot: offline ist ein Zustand, kein Fehler.
  • Erreichbarkeit: Die Leiste liegt oben; vertretbar, weil der Hinweis selten und rein informativ ist. Der handlungsnahe Zugang (Kreis antippen) liegt in der Liste.
  • SwiftUI: ToolbarItem(placement: .topBarTrailing) { Button { showOffline = true } label: { Image(systemName: "icloud.slash") } .tint(.secondary) .popover(isPresented: $showOffline) { VStack{…}.padding().presentationCompactAdaptation(.popover) } }; Zeitstempel über Text(date, format: .dateTime.day().month().hour().minute()); „Erneut versuchen“ ruft model.reload(). In TaskRow: Kreis mit .opacity(0.45) und gestricheltem StrokeStyle(dash:) bei !isWritable.
